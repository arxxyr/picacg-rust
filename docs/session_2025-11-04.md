### 2. 中文字体集成

#### 2.1 字体文件
- 字体名称：**Sarasa Term SC Nerd**（更纱黑体终端版 Nerd 字体）
- 字体文件：10 个 TTF 文件（Regular, Bold, Italic, 等）
- 存放位置：`resources/fonts/SarasaTermSCNerd/`
- 主要使用：`SarasaTermSCNerd-Regular.ttf`

#### 2.2 集成方式
- 使用 `include_bytes!` 在编译时嵌入字体
- 定义字体常量 `SARASA_TERM_FONT`
- 在 `iced::application` 构建器中配置字体：
  ```rust
  .font(include_bytes!("../../resources/fonts/..."))
  .default_font(SARASA_TERM_FONT)
  ```

#### 2.3 字体特性
- ✅ 完整的简体中文字符集
- ✅ 等宽字体（中文 2 字符宽度）
- ✅ 3000+ Nerd 图标
- ✅ SIL OFL 1.1 开源许可

#### 2.4 验证测试

### 4. 技术挑战与解决

#### 4.1 iced API 变更
**问题**: iced 0.13 移除了 `Application` trait，改用函数式 API
**解决**: 使用 `iced::application()` 构建器 + `iced::run()`

#### 4.2 生命周期问题
**问题**: `Element<'static, Message>` 与借用的 state 生命周期冲突
**解决**: 改为 `Element<'a, Message>` 并正确传播生命周期

#### 4.3 iced 组件 API 变化
**问题**:
- `Text::style()` 改为 `Text::color()`
- `text_input.password()` 改为 `text_input.secure(true)`
- `column.align_items()` 改为 `column.align_x()`
- `container.center_x()` 需要 `Length` 参数

**解决**: 查阅 iced 0.13 文档，使用新的 API

#### 4.4 ApiClient Clone
**问题**: 异步任务中需要 clone ApiClient，但未实现 Clone trait
**解决**: 为 `ApiClient` 和 `Signer` 派生/实现 `Clone` trait

## 遇到的问题与解决

### 问题 1: iced API 变更
**描述**: iced 0.13 移除了 `Application` trait
**影响**: 无法使用旧的 `Application::run()` 方法
**解决**:
- 使用 `iced::application()` 函数式 API
- 使用 `iced::run()` 启动应用
- 为 PicACGApp 实现 `Default` trait

### 问题 2: 字体路径
**描述**: `include_bytes!` 相对路径错误
**影响**: 编译时找不到字体文件
**解决**:
- 确认路径相对于 `src/ui/app.rs`
- 使用 `../../resources/fonts/...` 向上两级到项目根目录

### 问题 3: 生命周期冲突
**描述**: `Element<'static, Message>` 与借用的 state 冲突
**影响**: 无法编译
**解决**:
- 改为 `Element<'a, Message>`
- 正确传播生命周期参数

### 问题 4: 类型推断错误
**描述**: 错误处理中的 `Err(e: PicacgError)` 语法错误
**影响**: 编译失败
**解决**:
- 移除类型标注，改为 `Err(e)`
- 让 Rust 自动推断类型
